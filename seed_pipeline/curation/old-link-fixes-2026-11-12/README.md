## 2. 안 곡 (`fix.py`)

대상은 12명(`../new-catalog-links-2026-11-12/` 와 같음) 가운데 0501 전부터 작품 링크가 둘 다 있던 작품 35개 중 안 곡이 있는 16개와, 위에서 고친 작품이에요.

1. **앨범이 작품을 다 담았는지 먼저 봐요.** 아래 중 하나면 다 담은 것으로 봐요. 아니면 안 곡을 채우지 않아요.
   - `pick.evaluate` 로 센 작품 트랙이 곡 수 이상
   - 작품번호가 적힌 트랙이 곡 수 이상(「Transfigured Night, Op. 4」처럼 제목이 다른 말로 적힌 앨범)
   - 맨 위 곡의 8할 이상이 맞음. 이미 그 앨범 트랙을 가리키는 곡도 맞은 것으로 쳐요(곡마다 번호가 다른 타펠무지크)
   - 반만 든 「Vol. 1」이나 한 곡짜리 앨범은 여기서 걸려요.
2. **맞추기**
   - `../new-catalog-links-2026-11-12/pick.match_parts` 를 써요(match.py 의 match_set·match_children, 이름이 어긋나는 짝 거르기). 그 위에 셋을 더 봐요.
   - 곡마다 제 작품번호가 있는 묶음(타펠무지크 「TWV 55:e1」「TWV 43:G2」…): 그 번호 트랙 안에서 악장을 맞춰요.
   - 악장 번호 칸이 있는데 트랙이 「Z.570: No. 1 in D Minor, Ouverture」처럼 No. 로 적힌 앨범: 번호로 맞춰요.
   - 트랙에 작품번호가 없는 앨범(「Symphony No. 3 in G "The Great National"」): 조성을 뗀 본제목 구절로 맞춰요.
   - 더 본 짝도 이름이 어긋나거나 한 곡의 뒷부분이면 버려요.
   - 같은 곡 안의 악장은 앨범에서도 차례로 놓여야 해요. 앞 악장보다 앞 트랙을 가리키면 버려요
     (괴벨판 Spotify 에서 「TWV 41:h4」로 잘못 적힌 트리오 IV. Allegro 에 플루트 소나타 IV. Allegro 가 붙던 일).
     다른 곡끼리 같은 트랙을 가리키면 둘 다 버려요.
3. 이미 작품 링크로 고른 앨범이라, 작곡가 표기 거르기(요한 슈타미츠는 「Johann」이 있어야 함)는 앨범 이름으로 믿어요.

## 다시 만들기

`$W` 는 repo 밖의 작업 폴더예요.

```bash
cd seed_pipeline/curation/old-link-fixes-2026-11-12
# 운영 읽기 전용으로 export.sql 의 두 SELECT → $W/top.tsv, $W/parts.tsv
# 앨범 트랙: $W/want_<서비스>.txt 에 fixes.tsv 의 앨범과 지금 작품 앨범을 적고
(cd ../new-catalog-links-2026-11-12 && uv run python fetch_albums.py $W apple && uv run python fetch_albums.py $W spotify)
uv run python fix.py $W && cp $W/decisions.jsonl .
uv run python build_sql.py decisions.jsonl \
  --pieces ../../../migrations/202611120601_fix_old_piece_links.sql \
  --parts ../../../migrations/202611120602_fill_old_piece_part_links.sql
```

## 시험

운영 덤프(지금 시점, 마이그레이션 0502 까지)를 시험 DB(cm-linkfix-mysql)에 올려 두 파일을 트랜잭션으로 두 번 넣었어요.

- 작품·안 곡의 링크 칸을 넣기 전·1회 뒤·2회 뒤로 떠서 견줬어요. 1회 뒤와 2회 뒤가 같았어요(0.1초).
- 바뀐 칸 277개(작품 8, 안 곡 269)가 decisions 와 하나하나 같았어요. 그 밖의 칸은 바뀌지 않았어요.
- 값이 있던 칸은 바꿈 10곳만 바뀌었어요(작품 7, 안 곡 3).
- `test_apply.sh` 도 두 번째에 그대로였어요.
