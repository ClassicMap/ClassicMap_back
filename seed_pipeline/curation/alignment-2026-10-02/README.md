# 정렬 지도 2026-10-02

같은 구간 연주들의 같은 지점 표다. 결과는 `alignment-maps.jsonl` 이고,
`load_clip_alignments` 가 `clip_alignments` 에 넣는다. 화면의 1:1 "같은 지점" 전환과
동시 재생이 구간 안 비율 대신 이 표로 같은 마디를 찾는다.

## 만드는 방식 (`chroma-dtw-v1`)

- `scripts/build_alignment_maps.py`. 구간마다 연주의 화성 윤곽(chroma_cens, 클립 전체에서 잰
  조율 한 번)을 뽑아, 길이가 중간인 연주를 기준으로 DTW(코사인)로 맞춘다
- 기준 연주의 0.5초마다 이 연주의 같은 지점(ms)을 남긴다. 되돌아가지 않게 누적 최대로 편다.
  기준 연주 자신도 한 줄(그대로)이다
- hop 은 구간의 가장 긴 클립이 4000프레임을 넘지 않게 고른다(발췌 23ms, 전곡 9분 약 140ms)
- 비용(경로 길이로 나눈 남은 거리)이 0.11 을 넘으면 API 가 내보내지 않고 화면은 비율로 맞춘다.
  시드 검증의 교차 정렬 임계(`align.py` `COST_THRESHOLD`)와 같다
- 클립은 운영 공개 URL 에서 받아 `x-classicmap-clip-sha256` 으로 해시를 맞췄다. clipAssetId 는
  `loudness-2026-10-01/loudness-profiles.jsonl` 의 해시로 찾았다

## 차례

1. manifest 를 만든다. 클립 목록 SELECT 는 `loudness-2026-10-01/README.md` 와 같고
   `performanceId`, `sectorId` 를 함께 뽑는다
2. 클립을 한 폴더에 받는다(캐시 이름 `{영상 id}-{시작 ms}-{길이 ms}-{인코딩 판}.mp4`)
3. `python3 scripts/build_alignment_maps.py --manifest manifest.jsonl --clips-dir <폴더> > alignment-maps.jsonl`
   (numpy, librosa, av 필요. 맥북 6프로세스로 680클립 1분 23초)
4. 이 디렉터리에 커밋하고 배포한다(이미지의 `/app/seed/` 로 들어간다)
5. `deploy/alignment-load-job.yaml` 로 dry-run → 적재 → dry-run(계획 변경 0)
