# 같은 작곡가 안 중복 작품 정리 (2026-11-11)

작곡가 화면에 한 작품이 두 줄 이상으로 보이던 것을 하나로 합쳤어요(카르멘 193/11318, 애국가 340/11348 등).
마이그레이션은 `migrations/202611110501_merge_duplicate_pieces.sql` 이고, 묶음 35개에서 작품 37개를 숨겨요.

## 파일

| 파일 | 내용 |
|---|---|
| `find_candidates.py` | 운영 읽기 덤프에서 후보 짝을 뽑아요(제목 정규화·작품번호 묶음·손 작품과 영어 제목 닮음). |
| `candidates.tsv` | 11/11 덤프로 뽑은 후보 372짝. 후보일 뿐이고 하나씩 봤어요. |
| `decisions.json` | 진짜 중복으로 정한 묶음: 남길 작품, 숨길 작품, part 를 옮길지, 근거. |
| `gen_sql.py` | `decisions.json` → 마이그레이션. |

다시 만들기(`seed_pipeline` 에서):

```bash
curation/catalog-wave6-2026-11-10/tools/dump.sh <덤프 폴더>   # 운영 읽기 덤프
uv run python curation/duplicate-pieces-2026-11-11/find_candidates.py --db <덤프 폴더> > curation/duplicate-pieces-2026-11-11/candidates.tsv
uv run python curation/duplicate-pieces-2026-11-11/gen_sql.py --decisions curation/duplicate-pieces-2026-11-11/decisions.json --out ../migrations/202611110501_merge_duplicate_pieces.sql
```

## 어떻게 판단했나

이름만 같다고 합치지 않았어요. 후보마다 작품번호·조성·편성과 MusicBrainz work(`work-rels`, 판·편곡 관계,
disambiguation)를 대조해서 **같은 작품의 같은 판**만 중복으로 봤어요. 다음은 중복이 아니에요.

- 같은 이름의 다른 곡(작품번호·BWV·K.·Kk. 가 다름)
- 발췌와 전곡, 곡집 전체와 그 안의 권
- 다른 판·편곡(편성이 다른 판, 피아노 모음곡판, 노래판, 오페라와 부수음악)

후보 대부분은 `find_candidates.py` 가 찾았고, 두 묶음은 작곡가 작품 줄을 직접 보다가 찾았어요
(홀스트 10408 「Die Planeten」, C.P.E. 바흐 13224/13536 — 한쪽에만 H. 번호가 붙어 작품번호 묶음이 달랐어요).

## 남길 쪽 고르기

1. 비교 구간이 있는 작품(구간이 있으면 숨기지 않아요. 골드베르크 461 선례)
2. 「처음 듣는다면」 카드가 있는 작품
3. 사람이 손으로 넣은 작품(설명·우리말 제목·링크가 있음)
4. 그 밖에는 작품번호가 채워졌거나 제목이 더 정확한 쪽

예외: 보케리니 소나타 6번은 32874 를 남겼어요. 32874 의 악장이 낱곡 7754·8195·9633 을 품고 있어서,
9536 을 남기고 32874 를 숨기면 그 낱곡들이 작곡가 목록 맨 위로 튀어나와요(숨긴 묶음의 part 는 펼칠 길이 없어 낱곡을 목록에 남겨요).

## 마이그레이션이 하는 일 (숨길 작품마다)

1. **숨김**: `hidden_reason='duplicate'`. 제목이 그대로이고, 아직 보이고, 비교 구간이 없고, 다른 작품의 part 가 가리키지 않고,
   남길 작품이 보일 때만 숨겨요. 지우지 않으니 상세(`/pieces/<id>`)는 열려요.
2. **참조 옮기기**(1이 된 경우만): `information_schema` 로 찾은, `pieces.id` 를 가리키는 표의 행을 남길 작품으로 옮겨요.
   - 카탈로그 표: `piece_identifiers`(MBID·ISWC), `piece_aliases`, `piece_relations`(양쪽 끝, 남길 작품 자신과의 관계는 빼요),
     `composer_highlights`, `composer_major_pieces`, `piece_instrumentation`, `piece_reco_features`, `popular_comparisons`,
     `screen_music_cues`, `performances`, `track_piece_links`(part 없는 줄)
   - 사용자 표: `user_favorite_pieces`, `user_taste_seed_pieces`, `user_listening_events`
3. **빈 칸 채우기**: 남길 작품에 없는 설명(한·영 함께)·Spotify·Apple Music·YouTube Music 링크·작곡 연도를 숨긴 작품 값으로,
   대표곡 표시(잠기지 않았을 때)·`fame_score` 는 큰 쪽으로.
4. **part 옮기기**: `move_parts` 묶음만. 남길 작품에 part 가 하나도 없고, 숨긴 작품 part 에 겹 part 와 음원(track) 연결이 없을 때 통째로 옮겨요.
   남길 작품에 이미 part 가 있으면(카르멘 193 의 68곡 등) 옮기지 않아요.
5. **고침**: 두 묶음만.
   - 32874: 숨긴 9536 의 갈래(실내악·이중주 소나타)를 받아요(피아노·소나타였음).
   - 12256: 「2중창 E단조」(성악으로 잘못 옮김) → 「플루트와 바이올린을 위한 2중주 E단조」, 갈래 실내악·그 밖의 실내악.

두 번 넣어도 같아요. 숨긴 뒤에는 옮길 행이 없고 채우기·고침은 조건이 맞지 않아요.

### 유일 키가 있는 표 (사용자 표 포함)

`piece_aliases`·`piece_instrumentation`·`piece_reco_features`·`composer_major_pieces`·`composer_highlights`·`piece_relations`·
`performances`·`track_piece_links`·`user_favorite_pieces`·`user_taste_seed_pieces` 는 `UPDATE IGNORE` 로 옮겨요.
남길 작품에 같은 행이 이미 있으면(예: 한 사용자가 두 작품을 모두 즐겨찾기) 그 행은 옮기지 않고 숨긴 작품에 남겨요.
숨긴 작품 상세는 열리니 즐겨찾기가 끊기지 않고, 같은 사용자의 같은 작품이 두 번 생기지도 않아요.
`user_listening_events` 는 유일 키가 없어 모두 옮겨요. 11/11 운영 읽기 기준 숨길 작품 37개를 가리키는 사용자 행은 0건이에요.

## 시험

운영 카탈로그 읽기 덤프를 올린 시험 DB(`cm-dup-mysql`, 127.0.0.1:3412)에서:

- `catalog-wave6-2026-11-10/tools/test_apply.sh` 로 트랜잭션에 두 번 넣어 1.9초·1.6초, 두 번째에 pieces·piece_parts·식별자가 바뀌지 않았어요(idempotent).
  숨긴 작품 3,543 → 3,580(+37).
- 그 DB 로 띄운 백엔드가 `202611110501` 을 한 번 더 넣고 기록했어요(success).
- 남긴 작품 35개 `/api/pieces/<id>`·`/parts` 모두 200, 옮긴 part 수는 운영의 숨길 작품 part 수와 같아요.
- 작곡가 25명의 `pieceCount`·`/catalog` `total` 이 숨긴 수만큼 정확히 줄었고, 「처음 듣는다면」 카드는 운영과 같아요.
- 보이는 작품이 0인 작곡가 수는 60 그대로(전부터 있던 값), 갈래와 형식이 어긋난 작품 0, 숨긴 작품을 가리키는 공개 카드·관계 0.
