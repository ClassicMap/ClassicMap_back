# 비교 영상 S2 넷째 배치 검수 보고서

## 결론

베토벤·슈베르트 2곡에 연주 3종씩, 총 6개 후보를 적재해 발행했습니다.
함께 준비한 라흐마니노프 전주곡 C#단조 3건은 적재하지 못해 보류했습니다.

| 곡 | 연주 3종 | 구간 |
|---|---|---|
| 베토벤 바가텔 WoO 59 "엘리제를 위하여" | 랑랑 / 리시차 / 알리스 사라 오트 | 0–195 / 0–187 / 1–196초 |
| 슈베르트 악흥의 순간 D.780 제3번 | 조성진 / 다비드 프레 / 호로비츠 | 5–106 / 3–123 / 8–117초 |

## 검증 결과

교차 정렬은 여섯 쌍 모두 통과했습니다. 이번 배치는 걸러낸 것이 없습니다.

| 곡 | 정렬 비용 범위 | 길이 편차 |
|---|---|---|
| 엘리제를 위하여 | 0.0655 ~ 0.0742 | 1.04배 |
| 악흥의 순간 3번 | 0.0568 ~ 0.0911 | 1.18배 |

보류한 라흐마니노프도 정렬 자체는 0.0496~0.0716 으로 통과했습니다.
곡이 아니라 작품 연결이 막혔습니다.

## 라흐마니노프를 보류한 이유

셋째 배치의 달빛과 **같은 문제**입니다. 전주곡 C#단조의 MusicBrainz
work(`d0261eb5-…`)가 국제 시드 곡의 악장 part 로 이미 등록돼 있습니다.

```
piece 1920 "Morceaux de fantaisie, op. 3"
  musicbrainz:d0261eb5-7e04-3804-94f6-11f1439442a8
```

여기에 레거시 곡 229 의 식별자를 더하면 해소 대상이 2건이 되어 적재가 막힙니다.
구간과 검증 결과는 `held-rachmaninoff-prelude.json` 에 남겼습니다.

## 중복 규모

셋째 배치에서 "앞으로 반복된다"고 적었는데, 이번 배치에서 두 번 더 확인했습니다.
대체 곡으로 검토한 **사티 그노시엔 1번**(`eb07cf62-…`)도 국제 시드
piece 10942 "Trois Gnossiennes" 의 part 로 이미 있었습니다.

지금 규모는 이렇습니다.

| 항목 | 수 |
|---|---|
| 국제 시드 곡 | 18,155 |
| 국제 시드 낱곡 part | 28,274 |
| 레거시 곡 | 487 |
| 그중 MusicBrainz work 연결됨 | 53 |

연결되지 않은 레거시 곡 **434곡**은 연결을 시도할 때마다 충돌 여부를 확인해야
합니다. 지금까지 부딪힌 것은 달빛·라흐마니노프 전주곡·그노시엔 1번 3곡이고,
모두 **모음곡의 낱곡**이라는 공통점이 있습니다. 레거시는 유명한 낱곡을 독립된
곡으로 두었고 국제 시드는 모음곡을 악장 구조로 넣었기 때문입니다.

곡을 갈아끼워 피할 문제가 아니라 정리 방침이 필요한 문제입니다.

## 함께 고친 것

클립 선생성(`prewarm.mjs`)에서 `rangeVerifiedAt` 이 `assetValidatedAt` 보다
앞서는 일이 생겨 적재가 거부됐습니다. 두 값의 출처가 다릅니다.
앞은 클리퍼 서버 시계에서 오고 뒤는 실행 프로세스 시계에서 옵니다.
두 시계가 57ms 어긋나 순서가 뒤집혀 보였습니다.

검증은 언제나 자산이 준비된 뒤에 일어나므로, 자산 검증 시각 아래로는
내려가지 않게 맞췄습니다.
