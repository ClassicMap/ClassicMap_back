# 새 카탈로그 작품 링크 (2026-11-12)

11/11~12에 작품 목록을 넣은 작곡가 12명의 빈 Apple Music·Spotify 링크를 채웠어요.
리하르트 슈트라우스, 클레멘티, 요한 슈타미츠, 쇤베르크, 리게티, 텔레만, 퍼셀, 도메니코 스카를라티, 몬테베르디, 윤이상, 홍난파, 김동진이에요.

- 대상: 보이는 맨 위 작품(다른 작품의 안 곡이 아닌 것) 가운데 링크가 하나라도 빈 628개와 그 안 곡(곡 안 곡 포함) 2,490개.
- 마이그레이션: `migrations/202611120501_fill_new_catalog_piece_links.sql`(작품), `202611120502_fill_new_catalog_part_links.sql`(안 곡).
- 비어 있을 때만 채워요. 이미 있는 링크는 바꾸거나 지우지 않아요(틀려 보이는 것은 아래 「보고만 한 링크」).

## 순서

`$W`는 repo 밖의 작업 폴더예요. 검색·앨범 원본과 Spotify 웹 플레이어 요청(`captured.json`, 토큰 있음)은 거기에만 두고 커밋하지 않아요.

```bash

# 1. 운영 읽기 전용으로 export.sql 의 두 SELECT → $W/top.tsv, $W/parts.tsv
# 2. 검색(작품마다 검색어 둘, 첫 검색어로 쓸 앨범을 못 찾은 작품만 둘째 검색어)
uv run python search.py $W apple
PLAYWRIGHT_MODULE=<playwright> uv run python search.py $W spotify
# 3. 후보 앨범(검색 점수 앞 넷 + 지금 앨범 링크)의 전체 트랙
uv run python pick.py $W want
uv run python fetch_albums.py $W apple
uv run python fetch_albums.py $W spotify
# 4. 고르기 → $W/decisions.jsonl(이 폴더로 옮김), 한국 가곡은 후보를 보고 korean-picks.tsv 에 손으로 → korean-decisions.jsonl

  --pieces ../../../migrations/202611120501_fill_new_catalog_piece_links.sql \
  --parts ../../../migrations/202611120502_fill_new_catalog_part_links.sql
```

## 검색어 (`common.terms`)

- 작품번호가 있으면 「성 + 작품번호」(`Telemann TWV 55:C3`, `Scarlatti K. 25`), 그다음 「성 + 제목 앞 여섯 낱말」.
  작품번호가 범위(「SV 23–39」)면 제목만 써요.
- 윤이상은 「Isang Yun + 원어 제목」, 「윤이상 + 한글 제목」.
- 홍난파·김동진은 「한글 이름 + 한글 제목」, 「한글 제목 + 가곡(동요)」.
- Apple 은 iTunes Search(us, song, 200개, 3.3초 간격), Spotify 는 웹 플레이어 트랙 검색(100개, 1.5초)이에요.

## 고르는 규칙 (`pick.py`)

앨범마다 `../piece-album-links-2026-11-08/album_pick.pick`(작품번호·제목 구절·작곡가·원곡 음반·발췌 규칙)을 돌리고, 그 앞에 트랙을 걸러요.

- **같은 성의 다른 작곡가**: 요한·요제프 슈트라우스, 카를 슈타미츠, 알레산드로 스카를라티, 대니얼 퍼셀, 루카스 리게티 표기가 있으면 버려요.
  요한 슈타미츠는 「Johann」「J. Stamitz」「Stamic」, 윤이상은 「Isang」「윤이상」이 앨범·아티스트·트랙 어딘가에 있어야 해요.
  성 「Yun」만 보면 「Hyun」「Yunchan」에 걸려요. 스카를라티 성악곡(작품번호 없음)은 「Domenico」「D. Scarlatti」가 있어야 해요.
- **편곡**: 트랙이나 앨범 이름에 arr.·arranged·transcription·Bearbeitung·version for·기타·마림바판, 태교·힐링·오르골·자장가 따위가 있으면 버려요.
- **작품번호**: 「K. 3」은 「Kk. 3」도 봐요. TWV 의 조성 글자는 대소문자에 뜻이 있어(55:G2 장조, 55:g2 단조) 원래 꼴로 견줘요.
  범위 작품번호(몬테베르디 마드리갈 책, 퍼셀 소나타집)는 `album_pick` 이 못 읽어서, 범위 안 번호가 적힌 트랙을 세요.
- **조성**: 제목에 조성이 있으면 트랙의 작품 이름 쪽(첫 「:」 앞)에 적힌 조성이 같아야 해요.
- **여러 작곡가 모음 음반**
  - Spotify 는 클래식 트랙 아티스트에 작곡가를 적어서, 트랙 아티스트·이름에 작곡가 성이 있어야 해요.
    연습곡 모음의 쿨라우 「Sonatina Op. 20 No. 1」이 클레멘티 「Sonata Op. 20」으로 세지던 일을 막아요.
  - 앨범 이름이 「A: … - B: …」꼴이면 작품번호에 더해 제목 첫 낱말도 맞아야 해요.
    「Schoenberg: Violin Concerto - Sibelius: Violin Concerto」의 시벨리우스 Op. 47 이 쇤베르크 「Phantasy, Op. 47」로 세지던 일을 막아요.
  - Apple 은 아티스트에 연주자만 적는 일이 많아, Spotify 에서 작곡가를 확인한 앨범과 이름이 같은 앨범은 같은 음반으로 봐요(요한 슈타미츠).
- **작품번호 없는 작품**: 트랙에 작품번호가 있거나 제목과 다른 「No.」가 있으면 다른 작품이에요
  (쇤베르크 「String Quartet in D major」(1897) ↔ 「String Quartet No. 1, Op. 7」).
  같은 작곡가의 더 긴 제목을 품은 트랙(「Aventures」 ↔ 「Nouvelles aventures」)도 빼요.
  제목 구절이 트랙과 꼴이 달라 못 찾으면, 제목의 뜻 있는 낱말(편성 말 빼고, Violoncello=Cello)이 트랙 작품 부분에 다 있고 번호(Book·No.)가 같은지 봐요
  (리게티 「Concerto for Violoncello and Orchestra」 ↔ 「Cello Concerto」). 윤이상 「Bara」「Namo」처럼 짧은 제목은 트랙 작품 부분 첫머리가 같아야 해요.
  이 경우 앨범 이름이 그 작곡가로 시작하거나 트랙 아티스트·이름에 작곡가가 있어야 해요.
- **독일어 제목**: 「Waldhornkonzert」「Konzert für Horn und Orchester」 같은 갈래 말은 영어로 바꿔 견줘요.
- **곡 수**: 곡 안 곡이 있는 묶음(소나타 셋 → 악장 아홉)은 맨 끝 곡 수로 세요. 맨 위 곡 수로 세면 소나타 하나만 든 앨범이 묶음 전체로 보여요.
  악장으로 나눈 낱개 작품에 「Op. 20 No. 1: I. …」처럼 번호 붙은 다른 작품의 악장 트랙은 세지 않아요.

맨 위 작품

- **안 곡이 있는 작품**: 작품 트랙 수가 곡 수와 같은 앨범 → 곡 수 이상 → 앨범 이름에 작품번호·제목 → 검색 순서.
  곡 수 이상 든 앨범만 작품 링크로 써요. 일부만 든 앨범은 안 곡 링크에만 써요.
- **안 곡이 없는 작품**:
  - 작품 트랙이 하나면 그 트랙 링크(기존 스카를라티 소나타·사운드트랙 낱곡과 같은 꼴), 여러 트랙이면 앨범 링크예요.
  - 트랙 하나가 작품의 한 대목이면 쓰지 않아요. 작품번호 뒤 「:」 다음에 빠르기말이 아닌 이름이 있거나
    (「Celebrate This Festival, Z. 321: Crown the Altar」), 다른 후보 앨범에서 작품이 세 트랙 이상으로 나뉘어 있으면 그래요.
    스카를라티 「K. 3: Presto」처럼 빠르기말뿐이면 작품 전체예요.
  - 오페라·칸타타·미사·송가 같은 큰 작품은 트랙 하나(아리아)를 붙이지 않고, 앨범 이름이 그 작품이거나 작품 트랙이 넷 이상인 앨범만 써요.
  - 여러 트랙에 대목 번호(I.·No. 3)가 있으면 1부터 빠짐없이 있어야 해요(발췌 음반을 거른다).
  - 다른 후보 앨범에 든 대목의 절반도 안 되는 앨범은 발췌로 봐요(「Bonduca」 두 곡만 든 가곡 음반).
  - 같은 곡을 여러 판(리마스터·실황)으로 실은 앨범은 첫 트랙 링크예요.
  - 오페라(무대 작품)는 앨범 이름이 그 작품인 전곡 음반만 써요.
- **안 곡이 있는데 한 트랙에 통째로 든 녹음**(교향시 「Tod und Verklärung」)은 그 트랙 링크예요. 「:」 뒤에 대목 이름이 있으면 쓰지 않아요.
- 후보 앨범은 점수순으로 보다가 쓸 수 있는 첫 앨범을 골라요. 판정은 앨범 전체 트랙(iTunes Lookup·Spotify 임베드 앞 100곡)으로 다시 해요.
- 규칙으로 걸러지지 않은 것은 눈으로 보고 `review-skip.tsv`(작품, 서비스, 앨범, 까닭)에 적어 다음 후보를 보게 해요.

안 곡: 고른 앨범(링크가 이미 있던 서비스는 그 앨범)의 전체 트랙에 `../part-apple-links-2026-11-08/match.py` 의 `match_set`(맨 위 곡),
`match_children`(곡 안 곡)을 돌려요. 그 뒤 둘을 더 걸러요.
- 범위 작품번호로 붙인 트랙이 한 곡의 뒷부분(「SV 98b」)인데 이름이 다르면 버려요.
- 번호·악장·순서로 붙인 트랙의 곡 이름이 우리 곡 이름과 낱말 하나도 비슷하지 않으면 버려요.
  판본마다 악장 순서가 다른 텔레만 「La Bouffonne」(III. Rigaudon ↔ III. Les Boiteux), 1·2번이 바뀐 슈트라우스 Op. 29 음반 같은 경우예요.
  번역이 다른 이름(「Einleitung」 ↔ 「Prelude. Sonnenaufgang」)도 버려지지만, 틀린 링크보다 빈칸이 나아요.

## 시험

운영 카탈로그 덤프 시험 DB(`../catalog-wave6-2026-11-10/tools/devdb.sh`, cm-newlinks-mysql)에 두 파일을 트랜잭션으로 두 번 넣었어요.

- 링크 칸(작품·안 곡의 Apple·Spotify)을 넣기 전·1회 뒤·2회 뒤로 떠서 견줬어요. 1회 뒤와 2회 뒤가 같았어요(0.3초).
- 바뀐 칸 3,801개가 decisions 의 `fill`(작품 981 + 안 곡 2,820)과 하나하나 같았어요.
- 넣기 전에 값이 있던 칸, 12명 밖 작곡가의 행은 하나도 바뀌지 않았어요.
- `test_apply.sh` 의 작품·안 곡 해시(제목·작품번호 등)도 두 번째에 그대로였어요.
