# 작품 갈래·형식 바로잡기 2026-11-11

작곡가 화면의 갈래 묶음과 「처음 듣는다면」 카드 아이콘에 틀린 갈래가 보여서(「무언가」가 성악, 관현악 녹턴·소품이 피아노 등) 고쳤어요.
마이그레이션은 `migrations/202611110801_fix_piece_genres.sql`(작품 1,055곡)이고, 작품마다 옛값·새값·이유는 `changes.jsonl` 에 있어요.

## 무엇이 틀렸나

11/7 분류(`../piece-forms-2026-11-07/classify.py`)는 제목만 보고 갈래·형식을 붙여요. 그때 생긴 실수는 원인별로 이래요.

| 원인 | 예 | 고친 규칙 |
|---|---|---|
| 피아노 형식 규칙이 편성을 안 봄 | 「오케스트라를 위한 6개의 소품」(베베른)→피아노 소품, 타레가 기타 전주곡·연습곡→피아노, 「하프를 위한 즉흥곡」→피아노 | 건반 독주 규칙 앞에 **편성 관문**(`scoring`)을 둬요. 제목의 편성 자리(「for/pour/für/para/per …」, 「… solo」, 「…를 위한」, 「(바이올린과 피아노)」, 「첼로 로망스」)에서 악기를 읽어 관현악·독주와 관현악·성악·건반과 악기(실내악)·건반 아닌 독주로 먼저 나눠요. 「하프너」「포스트호른」「마술피리」「My Guitar…」 같은 별명·노래 제목은 편성으로 안 읽어요. |
| 「무언가(Lieder ohne Worte)」가 가곡 규칙에 먼저 걸림 | 멘델스존 무언가 8권→성악 | 「무언가·가사 없는·ohne Worte·without words·sans paroles」는 가곡 규칙에서 빼요(편성대로 피아노 소품·실내악). |
| 「(와/과) 관현악을 위한」이면 다 협주풍 | 「합창과 관현악을 위한 <밤의 노래>」→협주곡 | 협주곡 제목이나 목소리가 든 제목은 협주풍 규칙에서 빼요. 「Concerto pour violon」「Konzert für Klavier」처럼 독주 악기만 적은 협주곡은 그 악기의 협주곡 형식으로 넣어요(독주 둘 이상은 그 밖의 협주곡). |
| 「모음곡·세레나데·행진곡」이 편성 없이 관현악 | 「하프 독주를 위한 모음곡」·「세 대의 트럼펫을 위한 모음곡」→관현악 모음곡 | 편성 관문이 먼저 받아요. |
| 「코랄」이면 다 종교곡 | 「옛 체코 코랄에 의한 명상곡」(현악 4중주)→성악 | 악기가 적힌 코랄 제목은 종교곡으로 안 봐요. |
| 11/7 뒤 제목이 우리말로 바뀜 | 「Fantaisie pour violon et piano」가 11/7 에는 영어 제목이라 피아노 환상곡으로 남음 | 지금 제목으로 다시 돌린 값으로 고쳐요. |
| 제목만으로는 못 가리는 작곡가 | 소르·브라우어의 「환상곡」「소나타」(기타), 사라사테 「스페인 무곡」(바이올린과 피아노) | 기타 작곡가(타레가·소르·브라우어·요베트)는 피아노 형식으로 읽히면 기타 독주, 바이올린 작곡가(사라사테·크라이슬러·비에니아프스키)는 실내악, 알베니스의 세레나데·민속 무곡은 피아노예요. 파가니니(바이올린 독주·관현악·기타가 섞임)와 로드리고(피아노·기타가 섞임)는 피아노로 읽히면 비워 둬요. |

그 밖에 제목 규칙이 아예 못 붙이거나 틀리게 붙인 작품은 `classify.py` 의 `OVERRIDES`(작품 id → 형식, 줄마다 확인한 편성)와 `UNDECIDED`(편성을 확인 못 해 비워 둠)에 적었어요.
공개 카드(435곡)와 대표곡(notable) 전부를 한 줄씩 보고 고친 것도 여기 있어요(오르페오·수상 음악·밤의 가스파르·베르가마스크 모음곡·에니그마 변주곡·대푸가 등).

- 남은 원어 seed(origin='seed', editor_locked=0) 106곡: 같은 날 seed 정리(0601~)가 제목·묶음을 바꾸니 그 뒤에 다시 분류해요.
- 영화·TV·게임 작곡가 11명의 작품과 「영화음악·사운드트랙」 제목 105곡: 영화음악 갈래는 따로 다뤄요.
- 중복 정리 마이그레이션(0501)이 고치는 32874(보케리니)·12256(C.P.E. 바흐).
- 편성을 확인 못 한 것은 그대로 두거나(옛 값 유지 override) 비워요. 케이지 「4분 33초」는 편성이 없는 곡이라 '기타'로 둬요.

## 다시 만들기

`seed_pipeline` 에서

1. `curation/piece-genre-fixes-2026-11-11/tools/dump.sh <폴더>` — 운영 읽기 덤프(`classify_input.tsv`·`composers.tsv`·`piece_forms.tsv`).
2. `uv run python curation/piece-forms-2026-11-07/classify.py --input <폴더>/classify_input.tsv --genres curation/piece-genres-2026-11-07/genres.jsonl --out <폴더>/classes.jsonl`
3. `uv run python curation/piece-genre-fixes-2026-11-11/build_migration.py --db <폴더> --classes <폴더>/classes.jsonl --out ../migrations/<새 번호>_....sql --changes <changes.jsonl>`

이미 적용된 마이그레이션 파일은 고치지 않아요. 새로 고칠 땐 `classify.py` 규칙이나 `OVERRIDES` 를 고치고 새 번호로 만들어요.

## 시험

운영 카탈로그 읽기 덤프를 올린 시험 DB(cm-genre-mysql, 127.0.0.1:3413)에 한 트랜잭션으로 두 번 넣었어요. 1회 3.4초, 2회째 갈래·형식 해시가 같아요(멱등).
전후 모두 `piece_forms.genre` 와 `pieces.genre` 가 어긋난 작품 0, 형식만 있고 갈래 없는 작품 0, 갈래만 있고 형식 없는 작품 0이에요.
적용 뒤 시험 DB 로 다시 덤프·분류·생성하면 바꿀 작품이 0곡이에요(남는 차이는 위 '고치지 않은 것'뿐).
