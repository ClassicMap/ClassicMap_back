- `SPEC.md`: 작곡가별 에이전트에게 준 작업 명세예요. 범위, 단위, 이름 규칙, `catalog.json` 형식, 검증 기준이 있어요.
  명세에 나오는 `db/`(운영 읽기 덤프)와 `tools/fetch.py`(요청 간격을 맞춘 MusicBrainz·위키백과 수집기)는 작업 폴더에만 두었어요.
- `<작곡가>/catalog.json`: 넣는 작품만 담았어요. 뺀 작품과 까닭은 `report.md` 에 있어요.
- `<작곡가>/report.md`: 개수, 운영 기존 작품 대응, 뺀 것, 애매했던 판단, 직접 옮긴 우리말 이름, 위키백과 대조 결과예요.
- `gen_catalog.py`: `catalog.json` 을 마이그레이션 본문으로 바꿔요. 이름 규칙·제목 겹침·MBID 충돌에 걸리면 SQL 을 쓰지 않아요.
  마이그레이션 머리 주석은 손으로 적었고, 멘델스존 마이그레이션 끝의 123 작품번호 고침도 손으로 더했어요.

```bash
# seed_pipeline 에서. pieces.tsv·all_mbids_taken.tsv 는 운영에서 읽기만 해서 받은 TSV 예요.
uv run python curation/catalog-wave1-2026-10-11/gen_catalog.py --composer-id 15 --slug beethoven \
  --catalog curation/catalog-wave1-2026-10-11/beethoven/catalog.json \
  --pieces pieces.tsv --taken all_mbids_taken.tsv --out out.sql
```

처음 적용이 모두 합쳐 10초 남짓인 것을 확인했어요.
