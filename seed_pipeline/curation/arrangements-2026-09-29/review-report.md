# 편곡 비교 구간 검수 보고서 (2026-09-29)

편곡은 "같은 대목의 다른 해석" 이 아니라 "같은 작품의 다른 편성" 이고 그것은 그 자체로

## 임계를 무엇이 대신하는가

정렬 비용 임계(0.11)는 "같은 대목" 을 보장하려고 있다. 편곡 비교 구간은 그것을
보장하지 않으므로 다른 것을 보장한다.

| 해석 비교 | 편곡 비교 |
|---|---|
| 교차 정렬 < 0.11 | **적용하지 않는다.** 값은 기록만 한다 |
| 회전 최저가 0반음 | **적용하지 않는다.** 이조가 들을 거리의 일부다 |
| 같은 작품 MBID | 그대로 |
| 같은 악장·대목 | 그대로 |
| 배급 표기로 연주자 확인 | 그대로 |
| — | **배급 표기가 편성을 밝혀야 한다. 셋의 편성이 서로 달라야 한다** |
| 머리·꼬리 검출 확인 | 그대로 |

**"셋의 편성이 서로 달라야 한다" 가 새 조건이다.** 첼로 판 셋을 모으면 해석 비교인데
임계만 안 건 것이 된다. 다섯 곡 다 이 조건을 확인했다.

## 곡마다 갈리는 축이 다르다

- **374 리베르탱고 — 선율 악기.** A단조 두 화음 오스티나토는 거의 그대로이고 그 위에서
  선율 악기가 바뀐다. 길이가 2.23배 갈린다(176~394초)
- **375 망각 — 조성.** 회전 12방향으로 재면 카푸송↔로이드웨버의 최저가 10반음,
  로이드웨버↔크레메르가 2반음이다. 카푸송과 크레메르는 0반음으로 같은 조이고
  **로이드 웨버 판만 온음 낮다.** 그래서 0반음 교차값이 0.39 까지 오른다
- **377 여름 — 악기.** 셋 다 같은 조다(회전 최저 모두 0반음). 조성을 건드리지 않아
  들리는 차이가 거의 전부 악기의 차이다
- **181 생명의 양식 — 둘째 절.** 셋 다 테너 독창이고 셋 다 원조인 A장조다. 첫 절은
  0.109~0.147 로 붙고 둘째 절에서 0.145~0.215 로 벌어진다. A14 가 "삼등분에서 세 쌍
  모두 중간이 가장 나쁘다" 로 진단하고 멈춘 자리이고, 그 진단이 그대로 이 구간의 뜻이 됐다
- **376 아디오스 노니노 — 도입 카덴차.** 길이가 1.86배 갈린다(277~516초). 이 곡은

꼬리는 **원시 음량을 뒤에서부터 훑어 −50~−55dB 를 넘는 마지막 자리**로 잡았다
(`endpoint.py`). 평활화한 값을 쓰면 안 된다 — `np.convolve(..., mode='same')` 가 배열
밖을 0 으로 보고 dB 에서 0 은 풀스케일이라 끝자리가 부풀어 파일 끝이 늘 음악으로 잡힌다.

**편곡 비교에서는 사라지는 여운도 편곡의 일부다.** 검출기는 조성 곡선이 먼저 떨어져
일찍 끊는데, 해석 비교에서는 교차 정렬이 그것을 잡아 주지만 여기서는 임계가 없으므로
음량으로 직접 봐야 한다.

## 등록에서 세 갈래를 만났다

`genartists.py` 로 uuid5 를 계산하기 **전에** 확인해야 한다. 식별자 집합이 다르면
uuid5 도 달라서, 이미 있는 인물을 새 엔티티로 넣으면 같은 viaf·gnd·isni 가 두 엔티티에
붙어 `external_identifiers` 의 유니크 제약을 깬다.

| 자리 | 상태 | 할 일 | 실측 |
|---|---|---|---|
| 1 | `artists` 에 있다 | 등록하지 않는다 | **요요 마**(215). 그 엔티티 UUID 가 새로 계산한 값과 달랐다 |
| 2 | 엔티티는 있고 `artists` 행이 없다 | **행만 넣는다** | **크레메르**(843c0da2…) · **카레라스**(8adf0c99…) |
| 3 | 둘 다 없다 | 엔티티부터 만든다 | 발섬 · 에벤 · 로이드웨버 · 윌리엄스 · 쿠아르테토 · 크라이엔호프 · 티엠포 · 슈타인바허 · 두 단체 |

**2번이 두 번 나왔다.** 시드 앞단이 인물 엔티티를 미리 만들어 두고 artists 행은 배치에서
만드는 구조라 앞으로도 자주 나올 자리다.

## 화면

- 구간 칩에 **"편곡"** 표를 낸다(`sector-chip.tsx`)
- 고른 구간 아래에 **"편곡 비교 · 같은 작품을 다른 편성으로 듣습니다"** 와 감상 안내를
  그린다(`compare.tsx`)
- 안내는 배치 정의의 `sector.listeningNote` → `build_candidates.py` 의 `editorialNote`
  → 적재기의 `performance_sectors.description` 으로 흐른다. **이 경로는 이미 있었는데
  쓰이지 않고 있었다**
- `sector_type` 을 API 두 곳에 내보냈다. 프런트가 쓰는 `/pieces/{id}/sectors` 는
  `performance_sector` 모듈이라 `comparison` 모듈과 양쪽을 다 고쳐야 했다

실제 API 응답으로 끝까지 확인했다 — `{"id":259,...,"sectorType":"ARRANGEMENTS",
"description":"같은 탱고를 첼로·트럼펫·현악 4중주가 …"}`.

반주)은 편성이 갈려 편곡 비교로 쓸 수 있으나 **셋째 가수를 못 찾았다.** 목소리+오르간
편곡(`n37akUKdCLY`)과 목소리+하프 판은 있으나 가수에게 위키데이터 항목이 없다.

목소리와 악기를 섞으면 role_code 가 한쪽에서 틀린다.** 이것이 편곡 비교의 한 가지 한계다.
