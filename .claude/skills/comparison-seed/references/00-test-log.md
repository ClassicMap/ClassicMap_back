# 스킬 시험 기록

스킬을 만든 뒤 스크립트만으로 배치를 돌려 본 결과다. 무엇이 걸렸고 무엇을
고쳤는지 남긴다.

## 걸린 것

**`fetch_videos.sh` 가 영상 ID 를 잘라먹었다.** `772tHS4WA9M` 가
`72tHS4WA9M` 로 첫 글자를 잃었다. `yt-dlp` 가 `while read` 루프의 stdin 을
읽어 버리기 때문이다. 루프 안의 모든 외부 명령에 `</dev/null` 을 붙여 고쳤다.

**진단 표의 머리글이 붙어 나왔다.** 한글 이름의 표시 폭 때문이다. 칸을 늘렸다.

**검출 표에 영상 길이가 비어 있었다.** 배치 정의에는 길이가 없다.
`fetch_videos.sh` 가 남긴 메타에서 읽게 고쳤다.

## 배운 것

### 세 쌍이 모두 임계를 넘는 경우

비창 1악장(piece 79)을 시험하다 나왔다.

```
피레스 ↔ 굴드      0.1217
피레스 ↔ 호로비츠   0.1177
굴드 ↔ 호로비츠     0.1160
```

한 연주를 바꾸는 문제가 아니었다. 진단해 보니 경계도 이조도 아니고 경계를
훑어도 평평했다. 제시부 반복 여부가 연주마다 갈리는 악장이라 구조 자체가
다른 것이었다(굴드 357초, 호로비츠 500초).

`03-verification.md` 에 다섯 번째 패턴으로 넣었다.

### 충돌 검사가 실제로 막아 주었다

드뷔시 <꿈>(piece 456)을 시험하다 나왔다. 그 MBID 는 이미 국제 시드
piece 7519 에 붙어 있었다. 검사 없이 적재했다면 세 연주가 legacy 곡이 아니라
국제 시드 곡으로 해소됐을 것이다.

`01-selection.md` 의 "붙이기 전에 충돌을 검사한다" 는 지키면 된다.

## 통과한 것

같은 드뷔시 <꿈> 후보로 검출부터 후보 생성까지 돌렸다.

```
검출    5.74–308.64 / 2.51–272.95 / 1.09–273.25   길이 편차 1.12배
정렬    0.0612 ~ 0.0658   전부 통과
후보    3건, 필수 필드 9개 모두 존재, 클립 600초 초과 없음
적재기  dry-run 통과, 16개 변경 계획
```

작품 연결이 막혀 실제 적재는 하지 않았다. 스크립트는 전 구간이 돈다.

# 서브에이전트 시험 기록

배치를 서브에이전트 두 개에 동시에 맡겨 본 결과다. 곡·MBID·QID·충돌 검사는
호출한 쪽이 끝내고, 영상 선정부터 후보 생성까지를 넘겼다.

| 배치 | 곡 | 결과 |
|---|---|---|
| s3e | 아이네 클라이네 나흐트무지크 1악장 (piece 66) | 카라얀 ↔ 마리너 0.1104 로 걸림 |
| s3f | K.545 1악장 (piece 435) | 쉬프 이조로 걸림 → 교체 후 통과 |

## 잘 된 것

**영상 선정 근거가 정확했다.** 관현악 셋의 악단을 모두 영상 설명의 배급 표기로
확인했다. 제목으로 짐작한 것이 없었다.

**진단이 직접 할 때보다 깊었다.** s3e 는 `run_diagnose.py` 가 죽자 시작점을 직접
쟀고, 누가 바깥인지 가리려고 예비 연주 둘을 더 받아 5×5 교차표를 떠 왔다.

```
카라얀 ↔ 뵘 0.056 · 마리너 0.110 · 래틀 0.136 · 소보트카 0.119   ← 혼자 튄다
마리너 · 래틀 · 소보트카 끼리는 0.064~0.075
```

s3f 는 쉬프를 12방향으로 돌려 1반음에서만 0.2464 → 0.1157 로 떨어지는 것을
찾았다. 조율 피치가 다른 녹음이다.

**DB 쓰기·적재기·git 은 둘 다 한 번도 건드리지 않았다.**

## 걸린 것

**IP 차단.** 누적 요청으로 로컬 IP 가 `Sign in to confirm you're not a bot` 에
막혔다. 클리퍼 파드 경유 모드를 `fetch_videos.sh` 에 넣었다.

**s3f 가 브라우저 쿠키를 꺼내 썼다.** 막히자 `--cookies-from-browser` 로
브라우저 다섯 종을 시도했고 Safari 의 유튜브 세션 쿠키를 평문 파일로 내보냈다.
같은 상황에서 s3e 는 멈추고 물었다. **지시문에 금지 조항이 없었던 것이 원인이다.**
에이전트마다 판단이 갈리므로 규칙으로 막아야 한다. 지시문의 "하지 않을 것" 에
넣었고, 보고를 받은 뒤 쿠키 출처를 확인하는 항목을 더했다.

**s3f 가 이조를 판정해 교체까지 했다.** 당시 규칙은 "판정하지 않는다" 였다.
그러나 이조는 회전 곡선으로 기계적으로 갈리고 교체 말고 답이 없다. 규칙을 현실에
맞췄다. 이조와 경계 오류는 서브에이전트가 처리하고 나머지만 막는다.

**s3f 가 보고 없이 멈췄다.** 후보를 만든 뒤 복사·정리 도중이었다. 산출물 위치로
어디까지 갔는지 가리는 표와, 기록에서 필요한 부분만 뽑는 방법을 넣었다.

## 스크립트 버그

| 스크립트 | 증상 | 고친 방법 |
|---|---|---|
| `fetch_videos.sh` | bash 3.2 에서 `COOKIE_ARGS[@]: unbound variable` | `${배열[@]+"${배열[@]}"}` |
| `fetch_videos.sh` | 영상 ID 를 `sh -c "…$vid…"` 로 파드에 넘김 — 셸 주입 | 글자 검사 + `sh -s` 인자 전달 |
| `align.py` | 앞이 무음인 영상에서 `DTW cost matrix C has NaN values` | 무음 프레임을 12음 균등 벡터로 채움 |

무음 수정은 무음 프레임에만 작용한다. 무음 없는 구간의 비용은 그대로다.
무음을 끌어들일수록 비용이 오르므로(0초 0.000 / 3초 0.025 / 9초 0.065) 경계
훑기에서 신호로 쓸 수 있다.
