# 서브에이전트에게 배치 맡기기

배치 하나를 통째로 서브에이전트에게 넘긴다. 여러 배치를 동시에 돌릴 수 있고,
**툴 출력이 내 컨텍스트에 쌓이지 않는다.** 이것이 가장 큰 이득이다.

## 왜 하는가

한 세션에서 배치를 연달아 돌리면 검출 표·정렬 표·`yt-dlp` 로그·`mysql` 출력이
컨텍스트에 눌러앉는다. 실측한 세션에서 툴 결과로 되돌아온 문자가 930만 자
(약 230만 토큰)였고, 그 전부가 이후 모든 턴의 캐시 읽기에 곱해졌다.

서브에이전트는 그것을 자기 쪽에서 태우고 **보고 한 장만** 돌려준다.

| | 구간당 토큰 |
|---|---|
| 한 세션에서 연달아 | 19M (실측) |
| 새 세션마다 | 3~4M |
| 서브에이전트 | 2~3M + 병렬 |

## 무엇을 넘기고 무엇을 안 넘기는가

**시간이 오래 걸리고 되돌릴 수 있는 일**만 넘긴다. 되돌릴 수 없는 일은 넘기지
않는다.

```
서브에이전트                        호출한 쪽(나)
──────────────────────────────    ──────────────────────────────
영상 찾기·근거 확인                  곡 선정
오디오 수집                         작품 MBID 고르기
구간 검출                           충돌 검사
교차 정렬                           작곡가 QID 확인
어긋남 진단(이조·경계는 교체까지)       그 밖의 진단 판정
후보 JSONL 생성                     연주자 추가 마이그레이션
보고                               적재·발행·클립·커밋
```

경계는 하나로 외운다. **DB 에 쓰는 일은 전부 호출한 쪽이 한다.**

이유 셋:

1. 마이그레이션 번호가 순번이다. 둘이 동시에 잡으면 충돌한다
2. `seed_run_id` 가 겹치면 `DUPLICATE_RUN_ID` 로 죽고, dry-run 도 번호를 소비한다
3. 발행은 되돌리기 어렵다

**DB 읽기는 허용한다.** 연주자의 `wikidata` 를 직접 조회해야 영상을 제대로 고를
수 있다. 읽기를 막으면 이름으로 짐작하게 되고 그것이 더 위험하다.

## 진단: 기계로 갈리는 것만 맡긴다

`run_diagnose.py` 의 곡선 중에는 모양만 보면 답이 나오는 것이 있고, 곡을 알아야
답이 나오는 것이 있다. **앞의 것만 서브에이전트가 교체까지 한다.**

| 패턴 | 서브에이전트 | 근거 |
|---|---|---|
| 이조 | **교체해도 된다** | 12방향 회전에서 0 이 아닌 곳이 뚜렷이 최저 |
| 1번 경계 오류 | **고쳐도 된다** | 여러 쌍이 함께 내려감 |
| 2번 평평함 | 측정만 | 판본 차이인지 연주 차이인지 곡을 봐야 안다 |
| 3번 내려가다 멈춤 | 측정만 | 경계와 연주 문제가 섞여 있다 |
| 4번 한 점에서 급락 | 측정만 | 억지로 통과시키고 싶어지는 모양이다 |
| 5번 세 쌍 모두 넘음 | 측정만 | 곡의 반복 구조 문제라 연주를 바꿔도 안 된다 |

**이조**는 교체한다. 시험 배치에서 쉬프의 K.545 가 0반음 0.2464, 1반음 0.1157 로
갈렸다. 조율 피치가 다른 녹음이다. 구간을 고쳐서는 절대 맞출 수 없고 판단할
여지가 없다. 교체한 연주도 같은 규칙(공식 채널, 연주자 중복 금지)으로 고른다.

**경계 오류**는 `detected.json` 의 값을 고치고 다시 잰다. 되돌릴 수 있고 근거가
분명하다.

어느 쪽이든 **보고에 전후를 모두 적는다.** 교체했으면 빠진 연주와 그 비용, 회전
곡선을 남긴다. 경계를 고쳤으면 고치기 전후 값과 함께 내려간 쌍들을 남긴다.

나머지 넷은 "…로 보인다" 까지만 적고 멈춘다.

**예비 연주를 더 받아 교차표를 떠 오는 것은 허용한다.** 한 쌍만 걸렸을 때 누가
바깥인지 가리는 가장 빠른 방법이다. 시험 배치에서 카라얀만 넷 중 셋과 멀어진
것이 이렇게 드러났다. 다만 **두 개까지**만 받고, 배치 정의에는 넣지 않는다.

아래를 그대로 채워 쓴다. 배치 정의는 미리 만들어 경로로 준다.

````markdown

## 배치

정의 파일: <배치 정의 경로>

## 할 일

1. 곡마다 연주 3종을 찾는다. `01-selection.md` 의 규칙을 지킨다.
   - 공식 채널 우선, 같은 연주자 둘 금지, 600초 넘는 연주 제외
   - 관현악은 제목으로 악단을 알 수 없다. 영상 설명의 배급 표기를 근거로 삼는다
   - 연주자는 DB 에 `wikidata` 로 등록돼 있어야 한다. 조회해서 확인한다
   - 등록돼 있지 않으면 그 연주자를 쓰되 보고에 "미등록" 으로 적는다
2. 배치 정의의 `videos` 를 채운다
3. `fetch_videos.sh` → `run_detect.py` → `run_verify.py`
4. 임계를 넘으면 `run_diagnose.py` 로 곡선을 뜬다
   - 이조(회전 최저가 0반음이 아님)면 그 연주를 교체하고 다시 잰다
   - 여러 쌍이 함께 내려가는 경계 오류면 `detected.json` 을 고치고 다시 잰다
   - 그 밖의 모양이면 **판정하지 않는다.** 누가 바깥인지 가리려고 예비 연주를
     두 개까지 받아 교차표를 떠도 된다
5. 통과했으면 `build_candidates.py`
6. WAV 를 지운다. `detected.json` 과 `candidates.jsonl` 은 남긴다
7. 아래 형식으로 보고한다. **보고가 마지막 일이다.** 정리가 끝나면 반드시 보고로 끝낸다

## 하지 않을 것

- DB 에 쓰지 않는다. 마이그레이션을 만들지 않는다. 읽기만 한다
- 적재기를 돌리지 않는다. dry-run 도 돌리지 않는다 (run-id 를 소비한다)
- git 에 아무것도 하지 않는다
- 곡·MBID·QID 를 바꾸지 않는다. 막히면 보고에 적고 멈춘다
- `kubectl exec <pod> -- env` 를 통째로 찍지 않는다. 토큰이 노출된다
- 정렬 비용이 임계를 넘는데 구간을 옮겨 억지로 통과시키지 않는다
- **브라우저 쿠키를 쓰지 않는다.** `--cookies-from-browser` 는 사용자 계정
  자격증명이다. 파드에 마운트된 쿠키도 값을 꺼내거나 출력하지 않는다
- yt-dlp 가 막히면 **재시도를 걸지 않는다.** 두드릴수록 차단이 길어진다.
  보고하고 멈춘다
````

## 병렬로 돌릴 때

**작업 디렉터리를 배치마다 나눈다.** `detected.json` 은 `batchId` 로 갈리지만
WAV 는 `videoId` 로 저장되므로 같은 영상을 두 배치가 동시에 받으면 깨진다.

```
<스크래치패드>/comparison/<batchId>/
```

디스크는 배치당 WAV 9개 약 250MB 다. 셋을 동시에 돌리면 750MB 를 쓴다.
**끝나고 지우게 한다.** 지우지 않으면 금방 찬다.

동시에 셋을 넘기지 않는다. `yt-dlp` 가 같은 IP 에서 몰리면 막힌다.

**파드 경유를 기본으로 준다.** 로컬 IP 는 누적 요청으로 이미 막혀 있을 수 있고,
서브에이전트는 막히면 재시도를 걸어 차단을 더 길게 만든다. 지시문에 넣는다.

```bash
export COMPARISON_FETCH_POD=<클리퍼 파드 이름>
```

막혔을 때 **서브에이전트가 쿠키를 스스로 구하지 않게 한다.** 브라우저 쿠키는
사용자 계정 자격증명이다. 지시문의 "하지 않을 것" 에 적는다.

## 보고를 받은 뒤

### 보고가 오지 않으면

시험 배치에서 한 서브에이전트가 후보까지 만든 뒤 **보고 없이 멈췄다.** 산출물 복사와
정리를 하던 도중이었다. 알림만 기다리면 끝났는지 모른다.

**보고를 믿기 전에, 또 보고가 오지 않을 때 산출물을 직접 본다.**

```bash
W=<작업 디렉터리>; D=<curation 디렉터리>
ls -la "$W" "$D"
```

| 보이는 것 | 뜻 |
|---|---|
| `D` 에 `candidates.jsonl` | 끝까지 갔다 |
| `W` 에만 `candidates.jsonl` | 통과했으나 복사 전에 멈췄다. 직접 복사한다 |
| `detected.json` 만 있음 | 정렬에서 걸렸다 |
| WAV 만 있음 | 검출 전에 멈췄다 |
| 아무것도 없음 | 영상 선정이나 수집에서 막혔다 |

무엇을 했는지는 서브에이전트 기록에서 읽는다. 기록은 세션 디렉터리의
`subagents/agent-<이름>-*.jsonl` 에 있다. 툴 호출의 `description` 과 결과만
뽑으면 된다. **전부 읽지 않는다.** 그러면 컨텍스트를 아끼려고 서브에이전트를
쓴 의미가 사라진다.

```python
# tool_use 의 description 과, run_detect / run_verify / run_diagnose /
# build_candidates 가 들어간 명령의 tool_result 끝부분만 본다
```

`W` 에 WAV·`.npy`·쿠키 파일이 남았으면 지운다. 쿠키 파일은 값을 보지 않고 지운다.

### 반드시 볼 것

보고를 그대로 믿지 않는다. **네 가지를 반드시 본다.**

1. **영상 선정 근거** — 관현악에서 악단을 제목으로 짐작했는지. 같은 연주자가
   둘 들어갔는지. 채널이 공식인지
2. **정렬 비용의 분포** — 전부 임계 아래라도 한 쌍만 눈에 띄게 높으면 진단한다.
   서브에이전트는 임계만 보고 통과시킨다
3. **교체나 경계 수정을 했는지** — 했다면 근거가 규칙에 맞는지 본다. 이조는 회전
   최저가 뚜렷한지, 경계는 여러 쌍이 함께 내려갔는지. 한 쌍만 내려갔으면 그것은
   경계 문제가 아니다
4. **쿠키를 어디서 구했는지** — 수집이 됐는데 파드 경유가 아니었다면 기록에서
   `cookies` 를 찾는다. 브라우저에서 꺼냈으면 사용자에게 알린다

그다음 `04-loading.md` 로 간다. 충돌 검사는 배치를 만들 때 이미 했지만,
**적재 직전에 한 번 더 본다.** 다른 배치가 그 사이에 같은 MBID 를 붙였을 수 있다.
