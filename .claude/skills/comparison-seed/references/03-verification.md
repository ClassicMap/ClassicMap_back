# 교차 정렬과 어긋남 진단

세 연주가 같은 음악인지 재는 일이다. **이 단계가 배치의 안전망이다.**
지금까지 모든 배치에서 최소 한 건씩 걸러냈다.

## 어떻게 재는가

구간의 화성 윤곽(`chroma_cens`)을 뽑아 DTW 로 늘여 맞추고, 남는 거리를 경로
길이로 나눈다. 길이로 나누기 때문에 **템포가 달라도 비용이 커지지 않는다.**

```python
distance, path = librosa.sequence.dtw(X=a, Y=b, metric="cosine", subseq=False)
cost = distance[-1, -1] / len(path)
```

`subseq=False` 다. 시작점을 고정해서 잰다. 부분 일치를 허용하면 비슷한 다른
대목에 붙어 값이 나빠진다.

## 임계

**0.11** 이다. 통과한 배치는 대개 **0.04~0.09** 에 모인다.

임계 아래라도 **같은 곡의 다른 쌍보다 눈에 띄게 높으면 진단한다.**
0.10 대에서 통과시킨 뒤 판본이 다른 것으로 드러난 적이 여러 번 있다.

```
박쥐 서곡   카라얀 ↔ 클라이버 0.0583   카라얀 ↔ 메타 0.0964  ← 이 차이를 본다
```

## 길이로는 판정할 수 없다

| 곡 | 길이 편차 | 비용 | 판정 |
|---|---|---|---|
| 빗방울 전주곡 | 1.34배 | 0.066~0.074 | 통과 |
| 아라베스크 1번 | 1.35배 | 0.049~0.066 | 통과 |
| 월광 1악장 | 1.24배 | 0.044~0.049 | 통과 |

반대로 길이가 비슷해도 판본이 다르면 걸린다. **화성 진행만이 근거다.**

편성이 달라도 통과한다. 타이스 명상곡은 세 연주의 반주 편성이 서로 달랐는데
(피아노 / 관현악) 0.057~0.079 였다. 성악도 같다. 가사와 발음은 chroma 에 잡히지
않는다.

## 어긋남의 네 가지 모양

임계를 넘으면 `run_diagnose.py` 로 경계를 훑는다. **곡선의 모양이 원인을 말한다.**

### 1. 여러 쌍이 함께 내려감 → 경계 오류

```
쌍                 처음     274.7초로 보정
아슈케나지 ↔ 길렐스  0.1106  →  0.0984
아슈케나지 ↔ 레비트  0.0652  →  0.0471   ← 이 쌍도 함께 내려갔다
```

검출이 경계를 잘못 잡은 것이다. **값을 고쳐 쓴다.**
두 쌍이 함께 움직이는 것이 근거다. 연주가 다르면 한 쌍만 움직인다.

### 2. 어디로 옮겨도 평평함 → 판본·연주가 다름

```
끝(초)   565.5  568.5  571.5  574.5 ... 601.5
비용     0.106  0.108  0.109  0.110      0.110
```

경계 문제가 아니다. **연주를 교체한다.**
박쥐 서곡(메타), 발라드 1번(짐머만)이 이랬다.

### 3. 조금 내려가다 멈춤 → 연주가 다름

트로이메라이(호로비츠)가 0.1149 → 0.1087 까지만 내려갔다. 경계도 조금 문제였지만
그것만으로 설명되지 않는다. **교체한다.**

### 4. 특정 지점에서만 뚝 떨어짐 → DTW 경로 불안정

```
끝(초)   179.3  181.8  184.3  186.8  189.3 ... 199.3
비용     0.119  0.119  0.082  0.118  0.118      0.082
```

어느 경계에서든 0.08 이 나온다는 것은 같은 곡이라는 뜻이다. 다만 경로가 두
갈래로 갈리고 경계가 조금 달라지면 다른 쪽으로 빠진다. 라이브 연주의 늘임이
심하면 이렇게 된다.

**구간을 억지로 맞추면 통과하지만 그 값이 음악적 경계가 아니므로 교체한다.**
네순 도르마(플로레스)가 이랬다.

### 5. 세 쌍이 모두 넘음 → 곡이 연주마다 구조가 다름

```
피레스 ↔ 굴드      0.1217
피레스 ↔ 호로비츠   0.1177
굴드 ↔ 호로비츠     0.1160
```

한 연주가 아니라 **곡이 문제다.** 어느 하나를 바꿔도 낫지 않는다.

비창 1악장이 이랬다. 제시부 반복이 있고 연주자마다 반복 여부가 달라 구조가
갈린다. 굴드는 357초, 호로비츠는 500초였다. 진단해 보면 경계도 이조도 아니고
경계를 훑어도 평평하다.

**이런 곡은 그 구간을 포기한다.** 반복이 없는 다른 악장으로 가거나 다른 곡을
고른다. 비창은 2·3악장으로 갔다.

반복 구조가 갈리는 곡은 미리 의심한다. 고전 소나타의 1악장(제시부 반복),
쇼팽 즉흥환상곡, 리스트 사랑의 꿈이 그랬다.

## 이조

성악에서 한 번씩 나온다. 연주자가 음역에 맞춰 조를 옮기기 때문이다.
크로마를 12방향으로 돌려 본다. 특정 회전에서 뚝 떨어지면 이조다.

```
0반음 0.118   1반음 0.306   2반음 0.294 ...   ← 0이 최선이면 조성은 같다
```

## 곡 맨 앞은 취약하다

비용이 낮아도 틀릴 수 있다. 앞쪽 문맥이 없어 DTW 가 붙잡을 곳이 없기 때문이다.
라 캄파넬라 도입을 0.0616 으로 통과시켰는데 6.5초 틀렸던 적이 있다.

반복 음형은 원리적으로 위치를 특정할 수 없다. 그 곡의 5.0~8.0초 구간은 비용이
0.038~0.051 로 평평했다. **도입부를 따로 뽑을 때는 "음악 시작점 고정 + 길이
탐색"으로 다룬다.**

## 문맥을 포함해 재면 정확해진다

구간 앞뒤로 ±20초를 포함해 정렬하면 경계가 더 정확해진다. 라흐 3번 검증에서
확인했다. `run_verify.py` 는 구간만으로 재지만, 경계를 다툴 때는 문맥을 넣어
본다.

## 튜닝은 영상 단위로 고정한다 (2026-09-22 수정)

`chroma_cens` 에 튜닝을 맡기면 구간마다 새로 추정한다. 조율이 반음 경계 근처인 녹음은
경계가 0.1초만 달라도 추정이 1/3반음 반대쪽으로 뒤집혀 비용이 두 배로 뛰었다.
`align.tuning()` 이 영상 전체에서 고르게 뽑은 12조각으로 한 번 재고 저장해, 모든 구간에
같은 값을 쓴다.

실측(쇼팽 발라드 1번 루빈스타인, 시작점을 0.1초씩 21번 옮김):

| 쌍 | 옛 코드 | 새 코드 |
|---|---|---|
| 루빈스타인 ↔ 조성진 | 0.076~0.115 | 0.077~0.078 |
| 루빈스타인 ↔ 키신 | 0.068~0.115 | 0.068~0.071 |

이 버그로 **괜히 뺀 연주가 있다.** 루빈스타인은 발라드 세 섹터에서 0.11~0.14 로 걸려
뺐는데, 새 코드로는 0.063~0.078 이었다. 같은 섹터의 멀쩡한 쌍은 거의 그대로였다.
헝가리 광시곡 2번의 시돈도 같은 원인이었다(튜닝을 고정하면 0.08 대).

곡선에 **한 점만 뚝 떨어지거나 튀는 모양**(4번 패턴)이 보이면 먼저 이 버그를 의심했었다.
이제는 튜닝이 고정되므로 그 모양이 나오면 정말로 DTW 경로가 갈리는 것이다.

## 한 음만 반복하는 대목 (2026-09-24)

chroma 는 음높이를 12계급으로 접어 화성 윤곽을 본다. 그러므로 **한 음만 반복하는
대목에는 볼 것이 거의 없다.** 정렬 비용이 구조적으로 높게 나온다.

실측(버르토크 현·타·첼 3악장, S tier D4): 세 쌍이 0.0750~0.0990 으로 같은 배치의
다른 두 곡(0.059~0.067)보다 높았다. 진단하니

- 구간 삼등분에서 **어느 연주를 잡아도 앞 1/3 이 가장 나쁘고 중간이 가장 좋다**
  (앞 0.13/0.11, 중간 0.096/0.065, 뒤 0.077/0.069)
- 끝점 훑기가 평평하고(0.0984~0.1052) 최저와 현재 값의 차이가 0.0024다
- 12방향 회전에서 0반음이 최저다

**이조도 경계 오류도 아니다.** 3악장 도입은 실로폰이 F# 하나만 반복하는 대목이고,
세 쌍이 모두 그 구간에서만 오른다. 중간·뒤는 다른 곡과 같은 대역이다.

이런 모양이면 **판정하지 않고 그대로 둔다.** 시작점을 뒤로 옮길수록 비용이 내려가지만
(17.2초에서 0.0927) 섹터 큐가 그 도입을 가리키고 있으면 옮기지 않는다. 비용을 낮추려고
큐를 어기는 것이 더 나쁘다.

## 반음보다 작은 조율 차이 (2026-09-24)

지금까지 시대악기 연주를 **"이조로 걸린다"** 는 이유로 미리 빼 왔다. 실제 기제는
이조가 아니었다.

실측(마술피리 "밤의 여왕 아리아", 소프라노 다섯). 교차표가 **두 덩어리로 갈렸다.**

| | 담라우 | 드비엘헤 | 조수미 | 미클로샤 | 그루베로바 |
|---|---|---|---|---|---|
| 담라우 | — | 0.0676 | **0.1158** | 0.1083 | 0.0948 |
| 드비엘헤 | | — | 0.0988 | 0.1025 | 0.1008 |
| 조수미 | | | — | 0.0511 | 0.0566 |
| 미클로샤 | | | | — | 0.0503 |
| 그루베로바 | | | | | — |

**덩어리가 `align.tuning()` 값과 정확히 겹친다.**

| 연주 | 편성 | tuning(반음) |
|---|---|---|
| 담라우 | Le Cercle de l'Harmonie (시대악기) | −0.38 |
| 드비엘헤 | Ensemble Pygmalion (시대악기) | −0.38 |
| 조수미 | 빈 필하모닉 | +0.27 |
| 미클로샤 | 말러 체임버 | +0.17 |
| 그루베로바 | 취리히 오페라 | +0.16 |

**회전 곡선의 최저는 다섯 다 0반음이다.** 반음 이조가 아니다. 두 덩어리의 피치 차이는
0.65반음으로 반음보다 작고, 영상마다 조율을 보정하는데도 chroma 에 남는다.

그러므로 **진단에서 "이조 아님" 이 나와도 안심하지 못한다.** 곡선이 평평한 2번 패턴인데
연주들이 두 덩어리로 갈리면 `<vid>.tuning.json` 을 열어 본다. 값이 덩어리와 겹치면
편성 차이다.

**한 덩어리로 통일한다.** 이 배치에서 임계를 넘은 것은 담라우 한 쌍뿐이었지만 드비엘헤도
함께 뺐다. 드비엘헤만 남기면 0.0511 / 0.0988 / 0.1025 로 두 쌍이 선에 붙은 채 분포가
갈린다. "통과" 가 아니라 "간신히 안 걸린" 것이다.

## tuning 값은 A=415 를 못 가린다 (2026-09-25)

**`librosa.estimate_tuning` 은 반음 단위 편차를 `[−0.5, +0.5)` 로 접어 돌려준다.**
A=415.30Hz 는 440 대비 **정확히 −1.000 반음**이라 접히면 **0.000** 이 된다.
그래서 A=415 시대악기 녹음이 현대악기와 똑같은 tuning 값으로 보인다.

실측(C.P.E. 바흐 첼로 협주곡 A단조, piece 104).

| 연주 | tuning | 실제 |
|---|---|---|
| Bylsma | −0.48 | A≈428 |
| Coin | −0.36 | — |
| Suzuki | **+0.04** | **A=415** (BIS/Bach Collegium Japan) |

Suzuki 의 `+0.04` 만 보면 현대 피치처럼 보인다. 그런데 리토르넬로 발췌로 회전을
뜨니 **최저가 1반음(0.0743)이고 0반음은 0.192** 였다. 평균 크로마 상위도 Bylsma 는
E·A(A단조), Suzuki 는 **D#·G#** 으로 계급이 통째로 하나 밀려 있다.

### 폭 규칙이 놓치는 자리

"한 곡의 tuning 폭이 0.3 반음을 넘으면 본다" 는 규칙은 **접힘 때문에 두 군데서
틀린다.**

- `−0.48` 과 `+0.48` 은 실제로 0.04 반음 차인데 **0.96 으로 읽어** 헛걸린다
- `−0.48` 과 `+0.04` 는 실제로 한 반음 차인데 **0.52 로 읽어** "조금 벌어졌다" 로만
  보인다. 104 가 이 경우였다

경계(±0.5) 가까운 값이 섞이면 폭은 믿을 수 없다.

### 그래서 회전을 같이 뜬다

**최종 구간에서 곡마다 회전을 확인한다.** 비용이 드는 일이 아니다. 최저가 0반음이
아니면 이조이고, `06-subagent.md` 의 규칙대로 그 연주를 교체한다.

tuning 값은 **버리지 않는다.** 반음보다 작은 차이(위의 밤의 여왕 0.65반음)는 회전으로
안 잡히고 tuning 으로만 보인다. 둘은 서로를 대신하지 못한다.

| 보는 것 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| `tuning` 값 | 반음보다 작은 조율 차이 | 정확히 한 반음(A=415), 접힘 경계 |
| 회전 곡선 | 반음 단위 이조 | 반음보다 작은 차이 |

## 표기는 맞는데 오디오가 다른 트랙 (2026-09-25)

**공식 Topic 채널의 배급 표기가 정확한데도 오디오가 다른 곡일 수 있다.**

실측(C.P.E. 바흐 첼로 협주곡, Christophe Coin `0AlwJbA1Nr4`). 자동 생성 표기는
`Cello Concerto in A Minor, Wq.170/H.432: I. Allegro assai · Christophe Coin ·
Orquesta Barroca de Sevilla · ℗ 2019 Passacaille` 로 흠이 없다. 길이 517초도
1악장으로 그럴듯하다.

그런데 **12방향 회전 어디에도 최저가 없다**(0.194~0.321). 발췌가 아니라 전악장끼리
비교해도 같다(0.154~0.272). 같은 조건의 대조군은 0.030~0.044 다.

평균 크로마 상위가 Bylsma E·A, Suzuki D#·G# 인데 **Coin 만 G·F·B♭** 이다. 조율을
여섯 값으로 바꿔 다시 뽑아도 상위가 G·F 로 고정이다. binning 오차로 번진 것이
아니라 **내용이 A단조가 아니다.** 음반 이름이 "Cello Concertos"(복수)이고 C.P.E.
바흐의 첼로 협주곡은 Wq 170 A단조·Wq 171 B♭장조·Wq 172 A장조 셋이므로, 같은
음반의 다른 협주곡 트랙이 올라간 것으로 보인다.

**선정 단계에서는 보이지 않는다.** 제목·채널·배급 표기·길이가 모두 정상이었다.
오디오를 받아 재야만 드러난다. 그러니 **"표기가 맞으니 같은 곡이다" 로 넘기지
않는다.** 교차 정렬이 이것을 잡는 마지막 관문이다.

구별법은 이렇다.

| | 이조 | 다른 트랙 |
|---|---|---|
| 회전 곡선 | 0 아닌 곳에 뚜렷한 최저 | 어디에도 최저 없음 |
| 전악장 비교 | 같은 회전에서 내려감 | 여전히 최저 없음 |
| 평균 크로마 | 계급이 통째로 밀림 | 조성 자체가 다름 |
